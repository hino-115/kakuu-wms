# 要求分析書

## 1. 企業・業務の概要

### 1.1 企業概要

株式会社KAKUUは、コーヒー豆の仕入れおよび卸売を行う架空の企業である。

主に国内外のコーヒー豆仕入れ業者から商品を仕入れ、自社倉庫で在庫を管理した後、飲食店や小売店などの卸先へ商品を出荷している。

取扱商品はコーヒー豆を中心とした約10種類の商品で構成されており、商品の入荷から在庫管理、出荷までの一連の物流業務を行っている。

現在は専用の在庫管理システムを導入しておらず、Excelや紙、担当者の経験に依存した業務運用となっている。

| 項目 | 内容 |
|---|---|
| 会社名 | 株式会社KAKUU |
| 業種 | コーヒー豆の仕入れ・卸売業 |
| 取扱商品 | コーヒー豆 |
| 商品数 | 約10種類 |
| 仕入先 | 国内外のコーヒー豆仕入れ業者 |
| 販売先 | 飲食店・小売店などの卸先 |
| 在庫拠点 | 自社倉庫 |
| 現在の在庫管理方法 | Excelによる管理 |

### 1.2 業務概要

株式会社KAKUUでは、現在専用のウェアハウスマネジメントシステム（WMS）を導入しておらず、商品の在庫管理や入出荷業務をExcelベースで行っている。

仕入業務では、仕入れ業者へメールで発注を行い、発注した商品の情報をCSV形式のデータとして受領している。受領したCSVデータは担当者がExcelへ転記し、入荷商品の管理を行っている。

実際の倉庫内における在庫管理については、担当者が商品の数量や保管場所を把握し、人力による管理を行っている。そのため、Excel上の在庫数と実在庫数の照合作業なども担当者の確認に依存している。

卸先への出荷業務では、注文内容に基づいて担当者が倉庫内から商品を取り出し、ピッキング作業を行っている。ピッキング後の商品は検品を行ったうえで、佐川急便を利用して卸先へ発送している。

また、出荷に伴う領収書についてはExcelを用いて作成し、メールで卸先へ送付している。

## 2. 現状業務の分析

### 2.1 仕入れ業務

株式会社KAKUUでは、仕入れ業者への発注をメールで行っている。仕入れ業者から受領したCSVデータを担当者が確認し、Excelへ手作業で転記している。その後、商品が自社倉庫へ入荷され、担当者が実在庫を確認しながら管理している。

現在は、発注情報と入荷情報がExcelを中心に管理されており、専用の在庫管理システムとの連携は行われていない。そのため、CSVデータの転記や入荷内容の確認など、担当者の手作業に依存する工程が多い。

### 2.2 在庫管理業務

在庫数量はExcelに記録されているが、倉庫内の実在庫は担当者が人力で確認している。商品の入荷時や出荷時には、担当者が実際の商品数量を確認し、入荷出庫の作業を行い、その結果をExcelへ反映している。

また、商品には賞味期限が存在するため、商品単位だけでなくロット単位での管理が必要となる。しかし、現状ではExcel上での管理が中心であり、ロット情報を含めた在庫状況を迅速かつ正確に把握することが難しい。

### 2.3 出荷業務

卸先から注文を受けた担当者は、Excelを参照して在庫状況を確認する。その後、倉庫内の商品を人力でピッキングし、JANコードによる検品を行っている。

検品後の商品は佐川急便を利用して卸先へ発送する。発送が完了した後、担当者がExcelの在庫数量を更新するため、出荷と在庫更新の間に時間差が発生する場合がある。

### 2.4 請求・領収書業務

出荷後、担当者はExcelを使用して領収書を作成し、メールで卸先へ送付している。

領収書の作成や送付も手作業で行われているため、出荷情報と領収書情報の確認に手間がかかる。また、Excelファイルの管理方法によっては、過去の領収書を検索する際に時間を要する可能性がある。

### 2.5 業務全体の特徴

現状業務は、メール、CSV、Excel、紙資料、担当者による実地確認など、複数の手段を組み合わせて運用されている。

特に、発注・入荷・在庫管理・ピッキング・検品・発送・在庫更新の各工程が個別に管理されているため、業務間の情報連携が十分ではない。担当者の経験や確認作業に依存する部分が多く、業務量の増加や担当者の交代に対して、安定した運用を行うことが難しい状況である。

## 3. 現状の課題

### 3.1 Excelへの手作業による転記が多い

仕入れ業者から受領したCSVデータをExcelへ転記しているため、入力ミスや転記漏れが発生する可能性がある。

また、複数のExcelファイルを使用する場合、ファイル間で情報の不整合が発生しやすく、最新の情報を確認するために担当者が個別にファイルを確認する必要がある。

### 3.2 在庫情報をリアルタイムに把握しにくい

実在庫の確認とExcelの更新を人力で行っているため、実際の倉庫在庫とExcel上の在庫数量に差異が発生する可能性がある。

特に、出荷後に在庫更新を行う運用では、発送直後の在庫数量がすぐに反映されない場合があり、正確な在庫状況を把握しにくい。

### 3.3 賞味期限管理が難しい

コーヒー豆の商品には賞味期限があるため、同一商品であっても賞味期限ごとの在庫状況を管理する必要がある。

しかし、現状のExcel中心の管理では、賞味期限、入荷日、在庫数量などの情報を一元的に管理しにくく、在庫確認や出荷履歴の追跡に手間がかかる。

### 3.4 ピッキング作業の確認負担が大きい

ピッキング時には人力で商品を取り出しているため、担当者の経験に依存している。

商品数が増加した場合や類似商品を取り扱う場合、取り違えや数量間違いが発生する可能性がある。また、ピッキング内容を後から確認する際にも、手作業による確認が必要となる。

### 3.5 出荷結果と在庫情報の連携が不十分である

JANコードによる検品は行っているものの、検品結果を専用のシステムで管理していない。そのため、検品した商品の情報を出荷する際に、在庫管理へ反映する作業が別途必要となる。

検品と在庫更新が連動していないことで、入力漏れや更新遅延が発生する可能性がある。

### 3.6 出荷・領収書管理の手間が大きい

佐川急便による発送後、Excelで在庫を更新し、さらにExcelで領収書を作成してメール送付している。

これらの作業が個別に行われているため、出荷情報と領収書情報の照合に時間がかかる。また、過去の出荷履歴や領収書を確認する場合も、複数のファイルを検索する必要がある。

### 3.7 担当者への依存度が高い

発注データの転記、実在庫の確認、ピッキング、在庫更新、領収書作成など、多くの工程が担当者の経験や判断に依存している。

担当者が不在の場合や業務量が増加した場合、作業の引き継ぎや品質の維持が難しくなる可能性がある。

### 3.8 商品数の増加に対応しにくい

現在の商品数は約10種類であるため、Excelを中心とした管理でも一定の運用が可能である。しかし、将来的にアメニティなどの商品カテゴリを追加する場合、商品数や管理項目が増加し、既存のExcel管理では対応が難しくなる可能性がある。

そのため、今後の商品カテゴリ追加を考慮した、拡張性のある在庫管理の仕組みが必要である。

## 4. システム導入の目的

本システムは、株式会社KAKUUにおける仕入れ、入荷、在庫管理、出荷、検品および在庫更新業務の一部を対象として、段階的に導入する運用システムである。

現行業務では、Excel、メール、CSVデータおよび担当者による実地確認を組み合わせて業務を行っている。そのため、すべての業務を一度にシステム化するのではなく、対象範囲を限定した部分導入から開始し、実際の業務運用を通じてシステムの有効性や課題を確認する方針とする。

### 4.1 在庫情報の一元管理

今回の部分導入では、対象範囲となる仕入れ、入荷、在庫、検品、出荷などの情報をシステム上で管理し、担当者が必要な情報を迅速かつ正確に確認できる環境を整備する。

既存のExcelによる管理をすべて廃止するのではなく、システム化の対象となる業務から段階的にデータベースを中心とした管理へ移行することで、情報の重複や更新漏れの削減を目指す。

### 4.2 在庫管理業務の効率化

仕入れ業者から受領したCSVデータの登録や、商品の入荷・出荷に伴う在庫情報の更新など、今回の対象範囲に含まれる業務を効率化する。

部分導入によって、手作業による転記や複数ファイルの確認作業を減らし、担当者の作業負担を軽減する。また、実際の運用結果を確認しながら、今後の改善点を整理する。

### 4.3 ロット単位での在庫管理の実現

コーヒー豆の商品について、商品情報だけでなく、ロット番号、賞味期限、入荷日、在庫数量などを管理できるようにする。

ロット単位で在庫状況を確認できる仕組みを整えることで、在庫の追跡性を高め、出荷時の確認や賞味期限管理など、対象範囲における業務の正確性向上を図る。

### 4.4 JANコードを活用した検品精度の向上

出荷時の検品にJANコードを活用し、注文商品と実際にピッキングした商品の一致を確認できるようにする。

検品結果をシステム上の在庫情報と連携させることで、商品違い、数量違い、在庫更新漏れなどの発生を抑制し、部分導入による検品業務の効果を確認する。

### 4.5 出荷業務の標準化

今回の対象範囲に含まれる注文処理、在庫確認、ピッキング、検品、発送、在庫更新などの業務手順を整理し、担当者による作業のばらつきを減らす。

ピッキング作業については、今回のシステム化範囲では引き続き担当者が人力で行うことを前提とし、システムは必要な情報の確認や検品結果の管理を中心に利用する。

作業内容を明確にすることで、担当者の経験や記憶に依存しすぎない運用を目指し、実際の運用を通じて業務手順の妥当性を確認する。

### 4.6 出荷後の情報管理の効率化

佐川急便による発送後の在庫更新や、領収書作成に必要な情報を管理し、出荷情報を確認しやすくする。

今回の部分導入では、出荷後の情報管理を対象範囲に含める一方、配送業者との自動連携などの追加機能については、初期運用の結果を踏まえて今後検討するものとする。

### 4.7 部分導入による運用検証

本システムは、実際の業務で継続的に利用することを前提とした運用システムとして導入する。

初期導入後は、利用者の操作性、業務効率化の効果、入力ミスや更新漏れの発生状況などを確認し、システムが現行業務に適合しているかを検証する。

運用によって得られた結果や利用者からの意見を整理し、必要に応じてシステムの改善や運用方法の見直しを行う。

### 4.8 今後のシステム拡張に向けた方針

新たな機能の導入については、初期導入時点で詳細を確定しないものとする。

まずは今回定義した対象範囲の運用を完了し、その結果をもとに、追加すべき機能、システム化する業務範囲、既存業務との連携方法などを改めて定義する。

これにより、実際の運用で明らかになった課題やニーズを反映した、段階的かつ実用的なシステム拡張を目指す。

### 4.9 業務品質と情報の信頼性向上

今回の対象範囲における情報をシステム上で適切に管理することで、在庫数量や出荷状況の正確性を高める。

担当者が共通の情報を参照できる環境を整備し、入力ミス、確認漏れ、情報の不整合を削減することで、安定した業務運用につなげる。

また、部分導入後の運用結果をもとに、今後のシステム追加や業務改善の方向性を検討する。

## 5. システムの対象範囲

今回導入する運用システムは、商品の仕入れから入荷、在庫管理、出荷までの業務の一部を対象とする。既存の業務やExcel等による管理方法をすべて置き換えるのではなく、対象となる業務から段階的にシステムを導入する。

### 5.1 対象業務

| No. | 対象業務 | 内容 |
|---|---|---|
| 1 | 商品管理 | 商品名、JANコード、商品カテゴリなどの商品情報を管理する。 |
| 2 | 仕入れ管理 | 受領したCSVデータをもとに仕入れ情報を登録する。 |
| 3 | 入荷管理 | 商品の入荷情報や入荷数量を管理する。 |
| 4 | 在庫管理 | 商品ごとの在庫数量を管理する。 |
| 5 | ロット管理 | ロット番号、入荷日、在庫数量などを管理する。 |
| 6 | 出荷管理 | 卸先からの注文情報や出荷対象商品を管理する。 |
| 7 | ピッキング管理 | 出荷指示に基づいて、ピッキングリストを作成する。 |
| 8 | 検品管理 | JANコードを利用して、ピッキングした商品を確認する。 |
| 9 | 在庫更新 | 検品確定後の在庫情報を更新する。 |
| 10 | 出荷履歴管理 | 発送した商品の履歴や出荷情報を確認できるようにする。 |

### 5.2 対象外または既存運用を継続する業務

今回の部分導入では、すべての業務をシステム化するものではない。導入対象外の業務については、従来のExcelやその他の既存運用を継続する。

また、システム導入後の運用状況や課題を確認したうえで、必要に応じて対象業務の拡大や追加機能の検討を行う。

### 5.3 対象範囲の考え方

本システムの対象範囲は、今回の導入目的である在庫情報の一元管理、在庫管理業務の効率化、検品精度の向上および出荷業務の標準化を実現するために必要な業務を中心とする。

| 5 | 保守運用 | 部分導入中は開発者が保守を行い、システムの完全導入後における保守・運用体制については、別途協議するものとする。 |
| 6 | バックアップ | 本ポートフォリオではバックアップ機能を実装しない。 |

### 9.3 今回のポートフォリオで実装しない主な制約機能

| No. | 対象外機能 | 内容 |
|---|---|---|
| 1 | バックアップ機能 | データベースの自動バックアップや復元処理 |
| 2 | 詳細な権限管理 | 権限マスタに基づく操作制御 |
| 3 | 高度なWebセキュリティ対策 | CSRF対策、XSS対策、SQLインジェクション対策などの実運用向け対策 |
| 4 | パスワード管理の高度化 | パスワード変更、有効期限管理、アカウントロックなど |
| 5 | 操作ログ管理 | 利用者の操作履歴や監査ログの記録・検索 |
| 6 | 障害通知・監視 | システム障害やサーバー異常を検知・通知する機能 |

## 10. 今後の拡張性

### 10.1 拡張方針

本システムは、部分導入およびポートフォリオとしての実装を前提としている。今後は、導入範囲の拡大や利用状況に応じて、機能の追加および運用体制の整備を行うものとする。

### 10.2 今後追加することが確定している対象範囲

今後、以下の機能および運用体制を追加・整備することが確定している。

| No. | 追加対象機能 | 内容 |
|---|---|---|
| 1 | 権限管理機能 | 利用者や担当者ごとに操作権限を設定し、権限に応じた機能の利用およびデータへのアクセスを管理できるようにする。 |
| 2 | バックアップ機能 | データベース等のシステムデータを定期的にバックアップし、障害やデータ損失が発生した場合に復元できるようにする。 |
| 3 | 保守・運用体制 | システムの安定稼働を維持するため、障害発生時の対応、問い合わせ対応、データ管理および定期的なメンテナンス等の保守・運用体制を整備する。 |
| 4 | 棚卸機能 | 棚卸作業に必要な在庫情報を管理し、実在庫とシステム上の在庫数量を確認・照合できるようにする。 |
| 5 | 佐川急便とのAPI連携 | 佐川急便とのAPI連携により、出荷情報や配送情報を連携できるようにする。 |
| 6 | ピッキング機能の実装 | ハンディターミナルを使用し、出荷指示に基づくピッキング作業をシステム上で実施できるようにする。 |
