過程等のメモ書き

システム化する範囲が広くなりすぎたため、すべての倉庫業務を一度に実装するのではなく、部分導入を前提として対象業務と対象外業務を整理しました。
これにより、ポートフォリオとして実装可能な規模を保ちながら、将来拡張も考慮できる構成に改善しました。

現行業務とシステム導入後の業務が混在して分かりにくくなったため、仕入れ・入荷・入庫・出荷・ピッキング・検品などの業務を分けて整理しました。
業務ごとの責任範囲が明確になり、その後の機能整理につなげやすくなりました。

入荷と在庫更新のタイミングが曖昧だったため、「商品が届いた時点」と「棚へ入庫した時点」を分けて考え、実在庫への加算は入庫実績登録時に行う方針へ整理しました。

コーヒー豆のロットをどの単位で管理するか決まっていなかったため、段ボールからオリコンへ移し替え、1オリコン＝1商品・1ロットとして管理する方式に整理しました。
これにより、保管場所とロットを結び付けて管理しやすくしました。

ピッキングまでシステム化すると実装範囲が大きくなるため、今回はシステムがピッキングリストを作成し、実際のピッキングは人が行う形にしました。
将来的にはハンディターミナルを利用したピッキングへ拡張できるよう、今回実装と将来機能を分けています。

検品と在庫減算のタイミングを整理した結果、JANコードによる検品結果を登録した時点で在庫を減算し、その後の出荷確定では再度在庫を減らさない方式にしました。二重更新を防ぎ、在庫更新の責任点を明確にしています。
