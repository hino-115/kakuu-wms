# KAKUU WMS｜非機能要件

## 1. 目的

本資料では、KAKUU WMSにおける非機能要件を整理する。

本ポートフォリオでは、業務機能および設計工程の確認を主目的とするため、実運用を想定した一部の非機能要件については実装対象外とする。

非機能要件は、以下の区分で整理する。

| 区分 | 内容 |
| --- | --- |
| 実装対象 | 本ポートフォリオ内で実装・確認を行う |
| 設計対象 | 要件または設計として整理するが、実装は行わない |
| 対象外 | 本ポートフォリオでは取り扱わない |

---

## 2. 性能・応答性

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| 画面応答時間 | 通常操作に支障のない応答速度を目標とする | 設計対象 |
| 一覧検索性能 | 商品・在庫・入荷予定・出荷データ等の検索について、実用上問題のない応答を目標とする | 設計対象 |
| CSV取込性能 | 一般的な業務利用を想定した件数を処理できること | 設計対象 |
| 大量データ性能試験 | 大規模データを用いた負荷試験は実施しない | 対象外 |
| 同時アクセス性能 | 多数ユーザーによる同時アクセス性能の検証は実施しない | 対象外 |

※具体的な目標値や性能測定方法については、必要に応じて基本設計以降で検討する。

---

## 3. 可用性

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| システム稼働率 | 稼働率の数値目標は設定しない | 対象外 |
| 冗長化 | サーバー・DB等の冗長構成は実装しない | 対象外 |
| 障害時自動切替 | フェイルオーバー構成は実装しない | 対象外 |
| 計画停止 | 開発・保守に伴う停止を許容する | 設計対象 |

---

## 4. バックアップ・復旧

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| データバックアップ | 本ポートフォリオでは実装しない | 対象外 |
| 自動バックアップ | 実装しない | 対象外 |
| 災害復旧 | DR環境は構築しない | 対象外 |
| リストア試験 | 実施しない | 対象外 |

---

## 5. セキュリティ

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| ログイン認証 | 社員によるログイン認証を行う | 実装対象 |
| ユーザー識別 | 社員単位でシステム利用者を識別する | 実装対象 |
| 権限制御 | 担当者・管理者等の役割に応じた利用範囲を考慮する | 対象外 |
| パスワード管理 | パスワードを平文で保持しない方式を採用する | 実装対象 |
| 通信暗号化 | 本番運用を想定したTLS証明書・HTTPS環境の構築は対象外とする | 対象外 |
| 脆弱性診断 | 専門的な脆弱性診断・ペネトレーションテストは実施しない | 対象外 |

---

## 6. ログ・監査

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| アプリケーションログ | システム動作確認に必要なログを出力する | 実装対象 |
| エラーログ | 処理失敗時の原因確認に必要なログを出力する | 実装対象 |
| 操作履歴 | 重要な操作について、操作した社員、操作日時、操作内容等を記録する | 実装対象 |
| 長期ログ保管 | 長期間のログ保管・アーカイブ運用は実施しない | 対象外 |
| 外部監査対応 | 監査証跡の提出機能等は対象外とする | 対象外 |

---

## 7. 運用・保守

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| マスタメンテナンス | システム上から主要マスタを管理できるようにする | 実装対象 |
| 障害調査 | ログ等を用いて原因確認できる構成を目指す | 設計対象 |
| 本番監視 | 監視サーバーや外部監視サービスは導入しない | 対象外 |
| アラート通知 | メール・チャット等による自動通知は実装しない | 対象外 |
| 運用手順書 | 必要に応じてポートフォリオ内で簡易的に整理する | 設計対象 |

---

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| 利用形態 | PCから利用するWebシステムを想定する | 実装対象 |
| 対応ブラウザ | 開発・検証で使用する主要ブラウザを対象とする | 実装対象 |
| スマートフォン対応 | スマートフォン専用画面は作成しない | 対象外 |
| タブレット最適化 | 専用レイアウトは実装しない | 対象外 |

---

## 9. データ保全・保持

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| データ整合性 | 在庫・入荷・出荷等の業務データの整合性を維持する | 実装対象 |
| DB制約 | 主キー・外部キー・一意制約等を適切に設定する | 実装対象 |
| データ保持期間 | 業務データの長期保持期間は定義しない | 対象外 |
| データ削除運用 | 定期削除・アーカイブ処理は実装しない | 対象外 |

---

## 10. 拡張性・保守性

| 項目 | 方針 | 区分 |
| --- | --- | --- |
| 機能分離 | 業務機能ごとに責務を分離した構成とする | 設計対象 |
| コード可読性 | 命名規則および実装ルールを統一する | 実装対象 |
| DB拡張性 | 後続機能追加を妨げないデータ構造を意識する | 設計対象 |
| 大規模分散構成 | マイクロサービス等の分散構成は対象外とする | 対象外 |
| 自動スケーリング | クラウド環境による自動スケールは対象外とする | 対象外 |

---

## 11. 対象外事項

本ポートフォリオでは、以下を主な対象外事項とする。

- 高可用性構成
- サーバー冗長化
- DB冗長化
- 自動バックアップ
- 災害復旧環境
- 大規模負荷試験
- 多数同時アクセス試験
- 本番監視基盤
- 自動アラート通知
- 専門的な脆弱性診断
- スマートフォン・タブレット専用UI
- ハンディターミナル連携
- 長期データアーカイブ
- 自動スケーリング
- 本番運用を想定したインフラ構築

---

## 12. 補足

対象外とした項目についても、実システムでは必要となる可能性がある。

本ポートフォリオでは、WMSの業務要件・設計・実装・テストの一連の工程を示すことを優先し、インフラ運用や大規模システム向けの非機能要件については対象外とする。
