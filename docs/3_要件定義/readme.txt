設計上の前提：
今回はオリコン内の段番号を1として保持し、将来的に段ごとの商品・ロット・数量を個別管理できるよう、拡張性を考慮する方針です。
仕入れ管理における数量の取り扱い
仕入れ管理では、受領したCSVをもとに仕入れ予定数量を登録する。登録時点では在庫数量を更新せず、実際の入荷時に検品を実施し、確認した数量をもとに入庫数量を確定する。


保留事項： 注文CSVの重複登録後の取り扱い、先入れ先出しの基準日、出荷情報修正後の再検品範囲、出荷確定時の在庫更新タイミングについては、後の機能要件で具体化します。
JANコードが出荷指示の商品と一致しなかった場合の処理は、別途機能要件で明確にしておきましょう。

出荷時の在庫更新タイミング
在庫管理のNo.36では、出荷検品の確定結果に基づいて在庫を更新するとしています。一方、出荷管理のNo.53では、検品完了後に作業者が確定ボタンを押す構成です。

在庫更新を「検品結果登録時」に行うのか、「出荷確定ボタンを押した時点」に行うのか、後の機能要件で明示するとよいです。
先入れ先出しと実際の出荷ロット
出荷管理では先入れ先出しで在庫を選定しますが、今回の人力ピッキングとJAN検品では、実際に取り出した商品のロット番号を照合しません。したがって、出荷指示で選定したロットと実際に出荷したロットが必ず一致するとは限りません。

これは以前決めた実装範囲に沿っているため、設計ミスというわけではありません。**「今回の先入れ先出しは出荷指示上の選定であり、実物のロット照合は将来のHTピッキングで対応する」**と備考に残すと、説明しやすくなります

ただし、認証管理との整合性を保つため、非機能要件には次の一文だけ残すことをおすすめします。
本システムでは、ユーザーIDとパスワードによる基本的な認証を実装する。高度なセキュリティ機能は今回の実装対象外とする。
